开发分支：`codex/multi-team-foundation`。本次修正把植保接入现有地图和工单入口，灌溉表单、地图脚本与样式不重新设计。界面和操作体验由用户验收。

## 本地运行

在项目根目录执行：

```powershell
.venv/Scripts/python.exe internal_server/scripts/run_multi_team_preview.py
```

打开 <http://127.0.0.1:8786/>。登录后仍然进入地图；`/ops/` 和身份切换也返回地图。
脚本只监听本机回环地址，使用 `.tmp-pm-review/multi-team-preview/db.sqlite3`，不读取真实业务库。
测试媒体、AI 目录独立，邮件使用内存后端，不启动生产同步、派工或邮件定时任务。
重启保留已填写的地点、工单、成员身份及共享变更，不自动重新启用已停用的成员。
更新代码后需重启此脚本，再重新读取页面。

## 用户验收顺序

1. 使用 `irrigation-manager` 登录，查看原地图、图层和工单弹窗。原工作类别、工作内容和区域选择继续使用原有组件，不替换现有表单。
2. 使用 `pest-field` 或 `pest-manager` 登录，首页为同一个地图入口。默认显示授权的共享绿地、本团队区域、建筑/房间、监测点与最近作业记录；不加载灌溉管网和用水资料。
3. 点击地图上的地点或“创建工单”。植保表单沿用原工单弹窗、班次 chip、日期/时间、作业人数、第三方人数、备注。作业地点使用与灌溉相同交互的搜索/类型/地图点选选择器，不逐个铺开 chip；工作类别及下级工作内容按文档的实际深度逐级显示 chip。
4. 选择“传粉昆虫 → 蜜蜂 → 自然筑巢 → 建筑 → 人工处理 → 报封堵工单”。可跨类别选择多项，已选内容保留完整路径，点击已选项可移除。同名节点按所属路径区分。
5. 提交后进入原 `/work-reports/` 工单入口查看记录。植保经理看到本团队记录，一线看到本人记录；保存路径与地点名称快照。植保工单不进入灌溉维修日志、统计或导出。
6. 用 `dual-role` 切换身份：仍返回地图，按当前团队显示地图元素和工单内容。未提交表单切换身份会提示；旧表单不能在另一个团队下提交。
7. 植保经理的“区域管理”可添加建筑、房间、监测点，编号可为 `LOBBY-A` 等任意格式或留空，不要求 CCU-SAT-Station 三段结构。地图定位和上级地点也可选。
8. 灌溉经理在地点管理中引用并共享原区域。共享读取的是原区域当前生效边界，不复制坐标；取消共享后，植保地图和填报选项均不可继续使用该地点。接收团队无权编辑或再次共享。
9. 植保账号访问 `/irrigation/`、原用户管理、AI 或其他未接入的灌溉入口应被拒绝。团队经理身份不赋予全局 staff 或旧 `ManagerProfile`。
10. 平台管理员可以分配经理身份；普通团队经理只能管理本团队普通成员，不能提升为经理或改变其他团队身份。

## 可选图钉标注

在“区域管理 → 新增/编辑地点 → 地图显示方式”选择：

- **自动**：有有效边界显示边界，无边界但有坐标时显示图钉。
- **图钉标注**：用一个大致位置表示地点，无需绘制精确轮廓。在编辑地图上点选位置，再次点选可移动图钉。

地点类型决定图钉的图标与颜色：室外区域为绿色叶片，建筑为蓝色建筑，楼层为靛色叠层，房间为紫色门，监测点为琥珀色靶标，其他地点为灰绿色标记。主地图、地点地图与编辑预览保持一致；放大到 z18 起显示名称标签，缩小时保留图钉。图层菜单带图钉图例。

编号仍可留空或使用任意格式。没有坐标时，地点保留在列表及工单选项中，不自动猜测位置或在地图上生成假坐标。房间、楼层不会自动继承上级坐标，需要显示时可自行点选大致位置。

共享地点只能由所属团队修改显示方式。将引用的灌溉区域切为图钉，仅改变新业务地图的表示，不删除原边界，也不影响原灌溉地图。

## 本批边界

- 文档 215 个条目（208 个普通节点、7 个附属步骤）保留父子路径、原行号和来源版本，接入实际工单填报；不是只有单独参考页。
- 多团队账号、业务地图、地点只读共享、工单归属及查询隔离已接通。
- 植保计划轮转、化学品/专用物料目录、业务专属扩展字段尚未接入，不向灌溉派工表直接加入植保任务。
- 原灌溉系统目前仍是一个兼容业务范围，不宣称已支持多个灌溉子团队各自独立的旧全局经理权限。
- `MULTI_TEAM_ENABLED=False` 仍是默认配置。本地预览单独启用；生产试点已于 2026-11-08 按用户授权启用，部署与备份记录见 `docs/reviews/2026-11-08-multi-team-production.md`。

## 后续环境启用准备

1. 备份并在副本执行 Django migrations（包含工单业务归属与植保明细迁移）。
2. 执行 `bootstrap_operations` 建立业务和团队。
3. 必要时在审核的账号副本上执行 `bootstrap_operations --assign-legacy`：仅映射尚无成员关系的旧有效账号，不提升全局权限或重新启用停用身份。
4. 确认管理员与团队名单，再启用 `MULTI_TEAM_ENABLED=True`。
5. 用 `import_pest_reference PM管理_层级结构整理版.md` 导入层级，逐一确认需要共享的区域。


## 管理员视图与批量操作（2026-11-08 补充）

- 平台管理员在地图顶部切换「平台管理员 / 灌溉经理 / 灌溉一线 / 植保经理 / 植保一线」。这是当前会话的显示视图；不修改真实权限、团队成员或历史工单归属。个人资料及账号列表按真实权限显示管理员，不把历史 Worker 关联当成一线角色。
- 同一业务的角色切换保留当前地图和瓦片；切换业务只替换地图组件，保留中心和缩放级别，并清理旧组件的监听与定时器。未提交表单在切换前提示确认，提交中禁止切换。
- 植保地图使用与灌溉共用的功能菜单组件，采用相同按钮位置、展开收起和移动端排列。
- 植保经理可在原区域管理入口或地图功能菜单批量新增：每行仅写名称也可；支持粘贴 Excel 单元格或上传 CSV。可选编号、类型、上级编号、纬度、经度和说明，一批最多 500 个。先预览、整体校验，再创建；失败不留下部分数据，重试不会重复创建。
- 地点管理支持勾选本页或全部筛选结果，批量共享/取消共享。原灌溉区域可一批引用并共享，继续读取当前生效边界。接收方不能修改或再次共享；平台管理员可在植保经理视图直接选择灌溉区域。
- 搜索、分页、保存、共享和批量新增只更新相关列表、状态或地图覆盖物，不刷新整页。以后新增交互也遵循此原则，保留滚动、筛选、地图视角和未受影响的输入；普通页面链接仍用于主动导航。

界面和交互体验仍由用户验收，不运行浏览器视觉检查。
