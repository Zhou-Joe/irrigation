# 手机反馈、一线种类与植保区域操作

## 行为变化

- 反馈页在手机上使用单列布局、16px 输入字号和更紧凑的输入区；照片移除按钮、文件选择与分页操作提供至少 44px 的触控区域。团队筛选横向滚动，长名称、正文和照片不会撑宽页面。
- 一线种类增加“植保一线”和“绿化一线”，与“灌溉一线”共同保存到注册申请和 Worker 资料。注册、两种审批入口、个人资料、用户列表、公告名单和员工 API 均使用保存的种类。登录 API 也返回种类。管理员编辑用户时读取账号实际启用状态，并仅在主动切换开关时提交启停修改。空部门使用原始值回填，修改种类不会把显示用的横线写入部门资料。
- 新注册的一线账号审批通过后，按种类加入对应业务的默认团队。植保一线进入植保团队，绿化一线进入新建的绿化团队。默认团队不可用或无法唯一确定时，整个审批事务回滚。已有账号的业务访问由团队成员身份决定，种类编辑用于维护资料分类。Django 后台审批复用注册审批服务，保留原密码哈希。
- 按用户要求新增独立绿化板块。首页显示“板块已创建，功能待开发。”，提供业务切换、个人账号和反馈入口。绿化业务使用独立团队身份。
- “其他团队区域”支持直接在地图点击区域或图钉切换选择。地图高亮、列表勾选和计数同步，地点、加入／移出操作与接收团队跨分页保留。地图选中的非当前页地点也会提交。全选后的取消项通过排除列表提交，服务端按当前筛选条件重新确定操作范围。地图刷新失败后清除旧几何，避免使用上一轮结果。手机地图操作栏直接显示保存失败原因。切换筛选条件、范围或团队时清空选择。
- 删除“共享灌溉区域”按钮、页面、视图和路由。旧路由返回 404；批量共享端点拒绝旧 `zones` / `source=irrigation` 请求并返回 410。原有地点、区域边界和授权数据保留，区域注册维护继续工作。
- 建筑资料提供直接编辑的“建筑方位”，默认东、南、西、北，可用顿号、逗号或换行增加东南、东北等选项。仅在方位内容实际变化时重新解析，保留既有选项编号和其他参数。未配置的旧建筑使用默认方位。名称编辑会保留空配置，历史导入可继续安装来源方位。已有 100 个选项和包含标点的合法标签可以保存，新增方位时也保留原标签。
- 鸟类撞击工作分支自动提供按建筑填写的撞击方向。方向使用可键盘操作的原生单选 chip，并提供“未记录”。建筑、楼层和房间优先继承可见上级的配置，原有字段归属随工单保存。多个工作分支请求同一建筑字段时合并填写，采用其中的必填要求。服务端验证选项并保存名称快照，原有历史选项保留规则继续适用。
