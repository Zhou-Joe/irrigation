# 多团队入口与工单呈现修正

首批实现把植保引到独立卡片工作台，层级仅作为只读目录。这不符合地图首页和实际工单填报的要求，本次改回现有入口。

## 最终行为

- `/` 继续是地图，按当前团队加载授权地点和图层；不增加新的业务首页。`/ops/`、登录和身份切换返回地图。
- 灌溉保留原 `map.js`、`dashboard-modal.js`、`dashboard.css` 和原工单提交主体；共享模板只增加植保条件分支及团队身份选择。
- 植保通过原地图弹窗与 `/mobile/workorder/v2/` 提交。直接复用原 `v2-*` 表单、chip 与底部弹窗样式，不使用先前的折叠树、复选框或地点多选列表。
- 文档层级进入实际填报数据，支持任意深度、跨类别多选、路径快照、按 ID 区分同名内容；班次、人数和时间沿用灌溉字段及工时计算。
- 工单存入已有 WorkReport，显式标记业务团队；植保明细保存目录版本、路径和地点快照。原灌溉默认查询排除植保记录，避免统计和导出混入。
- 同一地图数据接口按团队返回数据；同一工单列表/详情路径按团队和角色查询。共享对象不暴露灌溉备注、人员、工单统计或照片。
- 提交前验证团队、地点授权、目录、终端工作内容与公共字段；支持重复提交重放，身份变化先于重放检查。
- 默认关闭新业务。所有预览数据在独立本地数据库中，不修改生产。

## 代码验证

服务端回归覆盖 core 与 operations，包含地图接口、原灌溉模板分支、真实工单提交、跨团队/一线权限、幂等和非法输入。前端逻辑检查覆盖层级选择、多分支保留、同名路径、附属步骤、无效 ID，以及已有前端回归。

验证结果：Django 357 项，356 通过、1 项原有跳过；Node 83 项全部通过。迁移检查无未生成变更。重启 8786 独立预览后，入口、manifest 及更新后的植保资源 HTTP 检查通过。灌溉工作台 `/app/` 继续可用，只有植保的该入口重定向地图。

遵照用户要求，此次不进行浏览器视觉或操作体验验收，由用户在本地预览确认。旧卡片工作台截图只记录此前实现，不能作为此次效果说明。
